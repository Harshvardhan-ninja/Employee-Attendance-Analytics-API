# REVIEW.md

## Defects found in the starter application

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes()` | The calculation does not consistently handle IST-aware timestamps and does not explicitly normalize timestamps to IST before calculating lateness. | Pass a UTC timestamp representing 09:40:01 IST. The result may be calculated against the wrong wall-clock time. | Normalize the instant to IST before comparing it with the shift start. |
| 2 | `compute_late_minutes()` | The helper calculates minutes using floating-point seconds and truncates the result. Timestamp precision is not normalized to whole seconds as required by R1. | Test 09:40:01 and timestamps containing fractional seconds. | Truncate timestamps to whole seconds before calculations and use whole elapsed minutes. |
| 3 | `compute_late_minutes()` | The helper does not handle overnight shifts, where an early-morning punch-in may belong to the shift that started the previous day. | Test a 22:00–06:00 shift with a punch-in at 05:00 IST. | Determine the correct shift-start date for overnight shifts before calculating lateness. |
| 4 | `compute_work_hours()` | Python's built-in `round()` uses ties-to-even rounding, which does not guarantee the required half-up rounding. | Test a duration whose hours value is exactly halfway between two hundredths. | Use decimal arithmetic with `ROUND_HALF_UP` to round work hours to two decimal places. |
| 5 | `compute_work_hours()` | The helper does not normalize timestamps to whole seconds before calculating duration. | Supply punch-in or punch-out values containing fractional seconds. | Truncate both instants to whole seconds before computing the duration. |
| 6 | `compute_overtime()` | Overtime is returned for any positive duration after shift end, rather than only when the duration reaches 30 minutes. | For an 18:30 shift end, test a punch-out at 18:45. The expected overtime is 0, not 15. | Calculate whole elapsed minutes and return them only when the duration is at least 30 minutes. |
| 7 | `compute_overtime()` | The shift-end timestamp is always built on the supplied attendance date. Overnight shifts must end on the following calendar day. | Test a 22:00–06:00 shift with a punch-out at 06:45 IST. | Construct the correct shift-end date for overnight shifts. |
| 8 | `compute_overtime()` | The calculation does not normalize the punch-out timestamp and shift-end comparison to a consistent timezone or truncate instants to whole seconds. | Use UTC-stored datetimes or fractional-second timestamps. | Normalize timestamps consistently to IST for shift calculations and truncate instants before calculation. |
| 9 | `create_employee()` | Duplicate detection relies on a separate read before insertion, so concurrent requests can both pass the check. | Send simultaneous requests with the same `emp_code`. Both may pass `find_one()`. | Create a unique MongoDB index on `emp_code` and translate duplicate-key errors into HTTP 409. |
| 10 | `create_employee()` | `created_at` uses `datetime.now()`, which produces a naive local datetime rather than an explicitly controlled UTC instant. | Run the application on a host configured with a different timezone and inspect the stored creation timestamp. | Use an explicitly timezone-aware UTC timestamp and store a consistent BSON date. |
| 11 | `create_employee()` / `EmployeeIn` | Shift times and the joining date are plain strings without sufficient format and business-rule validation. Invalid values can be stored and later break attendance calculations or analytics. | Submit malformed times, an invalid calendar date, or identical shift start and end times. | Validate `HH:MM`, `YYYY-MM-DD`, real calendar dates, and the rule that shift start and end must differ. |
| 12 | `health()` | The endpoint always returns `{"status": "ok"}` without checking MongoDB availability. | Stop MongoDB and request `/health`; it still reports success. | Execute a MongoDB `ping` and return HTTP 503 when the database cannot be reached. |
| 13 | `list_employees()` | Pagination uses `page * page_size` as the skip offset. This skips the first page when `page=1`. | With 45 employees and `page_size=20`, request page 1. It starts at the 21st employee rather than the first. | Calculate the offset as `(page - 1) * page_size`. |
| 14 | `list_employees()` | The total count ignores the department filter. | Create employees in two departments and request one department. `total` includes employees from both departments. | Call `count_documents(q)` using the same filter as the item query. |
| 15 | `list_employees()` | Results are not sorted by `emp_code`, as required by the API contract. | Insert employees in a different order and request the list repeatedly. | Apply a deterministic ascending sort on `emp_code` before pagination. |
| 16 | `list_employees()` | Pagination parameters are not constrained to the required ranges. Zero or negative pages and page sizes above 100 can produce invalid or excessive results. | Request `page=0`, `page_size=0`, or `page_size=101`. | Validate that `page >= 1` and `1 <= page_size <= 100`. |
| 17 | `PunchInIn` / `punch_in()` | The status field accepts arbitrary strings, although only `PRESENT`, `WFH`, and `ON_DUTY` are valid for punch-in. | Submit `status="INVALID"` or `status="LEAVE"`. | Restrict the request model to the allowed punch-in statuses. |
| 18 | `punch_in()` | An unknown employee is not handled before the employee's shift is accessed. `emp` can be `None`, resulting in a server error instead of HTTP 404. | Punch in using an unregistered `emp_code`. | Check for the employee first and return HTTP 404 if absent. |
| 19 | `punch_in()` | A supplied timestamp is converted with the host's local timezone assumptions and is not explicitly interpreted and stored according to the contract. The attendance date must be the IST calendar date of the punch-in. | Submit an epoch-millisecond timestamp close to midnight UTC, where the IST date differs from the UTC date. | Parse epoch milliseconds as an instant, normalize to IST, truncate to whole seconds, and derive the date in IST. Store the normalized instant consistently. |
| 20 | `punch_in()` | The timestamp uses a truthiness check. An explicitly supplied value of `0` is treated as if no timestamp were supplied, instead of being processed or rejected by validation. | Submit `punched_at=0`. The endpoint silently substitutes the current time. | Check for `None` explicitly and validate the allowed timestamp range. |
| 21 | `punch_in()` | The endpoint does not reliably reject invalid or out-of-range timestamps before conversion. | Submit a negative or excessively large epoch-millisecond timestamp. Conversion can fail or produce an unintended date. | Validate the timestamp and return HTTP 422 for invalid values. |
| 22 | `punch_in()` | The punch-in duplicate check and insertion are separate operations, so simultaneous requests can create duplicate records for the same employee and date. | Send concurrent punch-in requests for the same employee and IST date. | Add a unique compound index on `(emp_code, date)` and handle duplicate-key errors as HTTP 409. |
| 23 | `punch_in()` | The helper calculations use the employee's shift start without first applying the required timestamp normalization and overnight-shift logic. | Test fractional-second timestamps and overnight shifts around midnight. | Normalize the timestamp and use a shared shift-aware calculation that handles overnight shifts correctly. |
| 24 | `list_attendance()` | The endpoint loads every matching attendance record into Python, sorts the full result set, and only then paginates. This is inefficient for the required dataset size. | Seed approximately 100,000 attendance records and request a small page. The application still retrieves and sorts all matches. | Apply filters, sorting, skip, and limit in MongoDB and create appropriate indexes. |
| 25 | `list_attendance()` | The date filters are treated as unvalidated strings. Malformed dates can be accepted as query values instead of producing HTTP 422. | Request `/attendance?date_from=not-a-date`. | Validate date parameters as real `YYYY-MM-DD` calendar dates. |
| 26 | `list_attendance()` | The endpoint does not constrain pagination parameters to the contract's valid ranges. | Request `page=0`, a negative page size, or `page_size=101`. | Enforce `page >= 1` and `1 <= page_size <= 100`. |
| 27 | `list_attendance()` | The query does not have an appropriate guaranteed index-backed execution path, and sorting occurs in Python. This fails the requirement for fast, index-backed listing at scale. | Inspect the query plan on a large dataset or compare latency as records grow. | Create suitable indexes for employee/date filtering and date ordering, and move sorting and pagination into MongoDB. |
| 28 | Module initialization / database setup | The application does not create the required indexes at startup. In particular, uniqueness constraints and indexes needed for list and analytics queries are absent. | Start with an empty database and inspect the collection indexes; only the default `_id` indexes exist. | Create the required unique and query-supporting indexes during application startup. |
| 29 | `GET /attendance` response | The response returns MongoDB BSON datetimes directly rather than converting instant fields to epoch milliseconds as required by the API data model. | Inspect `punch_in` and `punch_out` in the JSON response. They are serialized as date strings instead of integer epoch milliseconds. | Convert stored instants, including nested history timestamps if present, to epoch milliseconds at the API boundary. |
| 30 | `POST /attendance/punch-in` response | The response contains the stored punch-in datetime rather than the required epoch-millisecond representation. | Inspect the `punch_in` field in the response. | Serialize the timestamp as an integer epoch-millisecond value. |

## Items examined and not considered defects

- **Default shift values:** `shift_start="09:30"` and `shift_end="18:30"` are valid defaults, provided the API contract permits them.
- **Default page size:** `page_size=20` is correct. The defect is the missing validation and incorrect pagination offset, not the default itself.
- **`compute_late_minutes()` grace-period comparison:** The `minutes > 10` check correctly excludes lateness at exactly 10 minutes when timestamps are already normalized and the elapsed time is calculated correctly. The surrounding timestamp and overnight-shift handling still needs fixing.
- **`compute_work_hours()` formula:** Subtracting punch-in from punch-out and converting seconds to hours is the correct basic formula. The rounding method and timestamp normalization are the defects.
- **`punch_out`, `work_hours`, and default attendance fields:** Initializing `punch_out` and `work_hours` to `None`, `overtime_minutes` to `0`, `half_day` to `False`, and `history` to an empty list is appropriate for an open attendance record.
- **`_id` removal in employee creation:** Removing `_id` before returning the employee is correct because MongoDB's internal identifier must not be exposed by the API.
- **Using `emp_code` as the employee identifier:** This is correct. The data model explicitly specifies that `emp_code`, rather than MongoDB's `_id`, identifies an employee.
- **Date filtering in `list_attendance()`:** Using inclusive `$gte` and `$lte` bounds for ISO-format calendar-date strings is appropriate when the inputs are validated and stored dates use the required `YYYY-MM-DD` format.
- **Missing Part B endpoints:** The punch-out, regularization, analytics, and explain endpoints are explicitly marked for implementation in Part B. They are incomplete features, not defects in the helper functions or endpoint implementations already supplied.
